# 产品设计

## 定位

ddflow 是依托外部 Agent Harness 的长工作流 Skill 工具包，以 Markdown 为工作流事实来源。降本增效是产品愿景，不作为验收指标。

优先面向多来源数据清洗与整理：字段映射、格式统一、有限语义判断、异常复核与可追溯交付。原始输入只读，结果写入新位置，排除或合并记录需要依据。固定规则批处理优先使用已有程序。

资料归档、研究准备与周期报告是后续候选场景。极短任务、缺少验收标准的开放探索及复杂动态调度不优先。软件开发可使用同一协议，但不默认附带编码、TDD 或 Git 流水线。

## 用户流程

1. 用户明确目标、输入、质量要求及可用模型，显式调用 Planner。
2. Planner 生成最小充分 DAG、任务 Contract 和模型分工，报告后停止。
3. 用户检查计划，另行显式调用 Executor，由宿主分派节点、验收产物并写回事实。
4. 需要改变 Contract、模型或 DAG 时交还用户显式 Re-plan；已启动任务真实收敛，已执行历史保留。

两个入口不能自动互相切换。具体状态、失败停图和写入规则以 [执行协议](../skills/protocol/execution-protocol.md) 为准。

## 交付

| 交付物 | 职责 |
|---|---|
| 双 Skill 包 | Planner 和 Executor 配套安装，分别显式调用，参考资料随包提供 |
| 可选 CLI 包 | inspect 确定性检查，view 本地只读展示 |

目标宿主为 Codex 和 ZCode。安装方式见 [安装说明](usage.md)，支持范围见 [宿主兼容性](usage.md#宿主差异与已知限制)。没有 CLI 时仍可按协议读取文档，但不能声称运行过确定性检查。

## 任务与质量

规划负责澄清目标、边界和验收；协调者负责执行秩序与验收；worker 在有限上下文中处理节点；复核能力按风险选择。

节点保持最小充分粒度，不为每行数据创建 Agent。主 Agent 读取必要摘要和证据，不反复复制整表或替每个 worker 重做业务。语义复核同时抽查待决项和 worker 自判正确的样本。

指定模型与思考强度必须通过宿主原生能力落实，不静默替换；实际模型证据缺失时如实记录未知。必要 Skill 必须进入 worker 上下文。

任务 Contract、确定性检查和宿主能力共同承担约束。用户接受的低风险试验可使用明确写入范围和主 Harness 验收的软约束；实际越界按执行协议停止。安装成功不证明一般执行保证。

## 范围

不自研 Runtime、Scheduler、Model Router、Provider / Secret 管理、统一 Adapter、数据库状态中心、动态 DAG、图形编辑器或后台 daemon。

实现职责见[架构](architecture.md)，操作方法见[使用](usage.md)。

## 当前能力

固定规则多来源汇总已完成限定验收；复杂语义清洗和电商教程业务执行尚未验证。Codex 已有部分原生发现与执行验证，ZCode 尚未完成安装发现与实际执行验证。更具体的宿主和工具限制见[使用说明](usage.md)。
